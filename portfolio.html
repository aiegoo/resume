API 서버와 LLM 서빙 엔진 사이에 **Redis Pub/Sub 기반 FIFO 작업 큐** 도입. 2. 최대 동시 슬롯 수(Batch Slots)를 4개로 제한하고, 초과 요청은 클라이언트에 `대기 순번(Queue Position)`을 실시간 푸시. 3. GGUF 4-bit 양자화(Q4_K_M) 적용으로 가중치 메모리를 14GB -> 4.8GB로 절감하여 KV 캐시 가용 메모리 대폭 확보. - **결과**: 동시 접속 50명 부하 테스트에서도 VRAM 점유율 78% 이하로 안정 유지 및 OOM 재발률 0%. ### [사례 2] 5G 무선망 핸드오버 시 WebRTC 영상 패킷 드롭 및 프리징 - **증상**: 드론이 이동 중 기지국 셀 변경(핸드오버) 구간을 통과할 때 WebRTC 비디오 스트림이 멈추거나 화면이 깨지는 현상 발생. - **원인 분석**: TCP 기반 시그널링과 UDP 기반 RTP 패킷의 순간적인 지터(Jitter)로 인해 키프레임(IDR Frame)이 유실됨. - **해결 방안**: 1. 지상 GCS 클라이언트에서 프레임 디코딩 실패 감지 시 즉시 RTCP PLI(Picture Loss Indication) 패킷을 기체로 역전송하도록 설정. 2. Raspberry Pi 인코더에서 PLI 수신 즉시 차기 프레임을 강제 IDR 키프레임으로 즉시 재발행. - **결과**: 무선망 핸드오버 발생 시에도 **0.3초 이내에 정상 화면으로 자동 복구** 완료. --- ## 6.
