### 1.2 하이브리드 검색 및 신체 금기 조건 필터링 공식 (Scoring Formula)
사용자의 자연어 질의와 함께 온보딩에서 등록된 신체 제약 조건($C_{\text{user}}$: 허리 디스크, 고혈압, 임신 등)을 감안하여 점수를 산출합니다. 위험 동작이 감지될 경우 해당 포즈의 가중치를 0으로 마스킹(Hard Filtering)하거나 강력한 페널티를 부과합니다:

$$Score = \left[ (1 - \alpha) \cdot S_{BM25} + \alpha \cdot S_{Vector} \right] \cdot \prod_{c \in C_{\text{user}}} \left( 1 - \mathbb{I}(c \in \text{Contraindications}_{\text{pose}}) \right)$$

- 일반 개념/증상 질의 (예: "허리 통증 완화 스트레칭"): $\alpha = 0.75$ (시맨틱 유사도 중심)
- 특정 고유명사 질의 (예: "비라바드라아사나 II 주의사항"): $\alpha = 0.30$ (BM25 키워드 정확 매칭 중심)
- 금기 충돌 시 ($\mathbb{I} = 1$): 스코어가 즉시 0으로 차단되어 사용자에게 안전한 대체 자세(Alternative Poses)만 컨텍스트로 전달.

### 3.1 설명가능한 AI (Model Explainability, XAI) 알고리즘
RAG 파이프라인에서 생성된 텍스트의 각 문장($S_i$)과 컨텍스트로 제공된 검색 청크($C_j$) 간의 역상관 유사도를 추적하여 사용자에게 근거 출처를 투명하게 제공합니다:

```python
def compute_sentence_attribution(generated_sentences, source_chunks, embed_fn):
    """
    각 생성 문장(S_i)과 검색 청크(C_j) 간의 코사인 유사도를 계산하여
    신뢰도 스코어와 원문 하이라이트 인덱스를 반환하는 XAI 엔진
    """
    chunk_embeddings = embed_fn([c["text"] for c in source_chunks])
    sentence_embeddings = embed_fn(generated_sentences)
    
    attribution_results = []
    for s_idx, s_vec in enumerate(sentence_embeddings):
        similarities = cosine_similarity([s_vec], chunk_embeddings)[0]
        best_chunk_idx = int(np.argmax(similarities))
        best_score = float(similarities[best_chunk_idx])
        
        attribution_results.append({
            "sentence": generated_sentences[s_idx],
            "source_chunk_id": source_chunks[best_chunk_idx]["id"],
            "confidence_score": round(best_score, 4),
            "is_grounded": best_score >= 0.72  # 0.72 미만은 근거 부족 경고
        })
    return attribution_results
```

### 3.2 AWS Bedrock 자동 폴백 (Failover Circuit Breaker)
사내 온프레미스 GPU 서버 또는 특정 LLM 인스턴스가 다운되거나 응답 타임아웃(3.0초) 발생 시, 서비스 단절 없이 AWS Bedrock Claude 3.5 Sonnet 엔드포인트로 자동 절체(Failover)되는 서킷 브레이커 패턴을 적용했습니다:

- **정상 상태 (Closed)**: 로컬 온프레미스 GPU vLLM 추론 수행 (비용 0원)
- **장애 감지 (Open)**: 연속 3회 타임아웃 발생 시 서킷 오픈 -> AWS Bedrock API로 라우팅 (전환 시간 < 1.2초)
- **복구 검증 (Half-Open)**: 60초 후 상태 프로브 요청을 전송하여 정상 응답 확인 시 로컬 GPU로 자동 복귀

WebSocket 클라이언트 C# 컴포넌트가 명령 큐(Command Queue)를 수신하여 Unity의 `FixedUpdate()` 물리 연산 루프에서 부드러운 가감속(S-Curve 가속도 제어)을 적용하여 기체 또는 로봇 메쉬의 물리적 충돌 및 자세를 시뮬레이션합니다.

## 5. 트러블슈팅 및 장애 대응 엔지니어링 케이스 스터디

### [사례 1] 로컬 LLM 동시 요청 시 GPU VRAM OOM(Out of Memory) 크래시
- **증상**: 다수의 사용자가 동시에 대화형 챗봇에 질의할 때 GPU VRAM이 한계(24GB)를 초과하여 LLM 서빙 프로세스가 비정상 종료되는 현상 발생.
- **원인 분석**: 단일 HTTP 요청마다 즉시 모델 인스턴스에 컨텍스트를 할당하여 동시 KV 캐시 메모리가 폭증함.
- **해결 방안**:
  1. API 서버와 LLM 서빙 엔진 사이에 **Redis Pub/Sub 기반 FIFO 작업 큐** 도입.
  2. 최대 동시 슬롯 수(Batch Slots)를 4개로 제한하고, 초과 요청은 클라이언트에 `대기 순번(Queue Position)`을 실시간 푸시.
  3. GGUF 4-bit 양자화(Q4_K_M) 적용으로 가중치 메모리를 14GB -> 4.8GB로 절감하여 KV 캐시 가용 메모리 대폭 확보.
- **결과**: 동시 접속 50명 부하 테스트에서도 VRAM 점유율 78% 이하로 안정 유지 및 OOM 재발률 0%.

### [사례 2] 5G 무선망 핸드오버 시 WebRTC 영상 패킷 드롭 및 프리징
- **증상**: 드론이 이동 중 기지국 셀 변경(핸드오버) 구간을 통과할 때 WebRTC 비디오 스트림이 멈추거나 화면이 깨지는 현상 발생.
- **원인 분석**: TCP 기반 시그널링과 UDP 기반 RTP 패킷의 순간적인 지터(Jitter)로 인해 키프레임(IDR Frame)이 유실됨.
- **해결 방안**:
  1. 지상 GCS 클라이언트에서 프레임 디코딩 실패 감지 시 즉시 RTCP PLI(Picture Loss Indication) 패킷을 기체로 역전송하도록 설정.
  2. Raspberry Pi 인코더에서 PLI 수신 즉시 차기 프레임을 강제 IDR 키프레임으로 즉시 재발행.
- **결과**: 무선망 핸드오버 발생 시에도 **0.3초 이내에 정상 화면으로 자동 복구** 완료.
